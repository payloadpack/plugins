<Steps>

1. **Install the package.**

   ```sh
   bun add @payloadpack/path
   ```

   Or use `npm install`, `pnpm add`, or `yarn add`. Peer dependencies: `payload`, `@payloadcms/ui`, and `react`.

2. **Add the plugin.** Place it after any plugin that adds one of its collections.

   ```ts title="payload.config.ts"
   import { pathPlugin } from '@payloadpack/path'

   export default buildConfig({
     plugins: [pathPlugin({ collections: ['pages', 'posts'] })]
   })
   ```

   <SidebarPreview />

   Pages sit below pages and posts below posts. See [Collections](/path/configuration/#collections) for base paths like `/blog`, flat collections without a parent, and Payload's hierarchy.

3. **Generate the import map** so Payload registers the slug field component (`@payloadpack/path/client#SlugField`). Payload's dev server does this automatically.

   ```sh
   bunx payload generate:importmap
   ```

4. **Create a migration** on Postgres and SQLite for [the fields the plugin adds](/path/configuration/#the-fields-it-adds). In development with `push: true`, Payload adds the columns automatically.

   ```sh
   bunx payload migrate:create
   ```

5. **Backfill existing documents** created before you added the plugin. Run this once in a script or [migration](/path/api/backfill-paths/#how-to-run-it). New saves get their paths automatically.

   ```ts
   import { backfillPaths } from '@payloadpack/path'

   const { left, unchanged, updated } = await backfillPaths({ payload })
   ```

   If a collection with [Payload's hierarchy](/path/configuration/#payloads-hierarchy) already has documents with parents, run this before deleting anything in it.

6. **Generate types** so your documents include `slug` and `path` (plus `parent` and `ancestors` on collections that [have them](/path/configuration/#the-fields-it-adds)).

   ```sh
   bunx payload generate:types
   ```

</Steps>

## Existing slug or parent fields

- Remove your own `slug` and `parent` fields first — the plugin [adds its own](/path/configuration/#when-the-config-is-wrong). If `@payloadcms/plugin-nested-docs` adds `parent`, remove that plugin from your config. Stored values in the database stay intact.
- Run `backfillPaths` to build each document's path from those stored slugs and parents.
- On a localized site, a slug that isn't localized today stays one slug for every locale unless you set [`localized: true`](/path/configuration/#a-path-per-locale).

## Transactions

| Database setup                  | If a save, move, or delete fails                                                                                     |
| ------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| With transactions               | Everything rolls back and stays as it was                                                                            |
| Without them (SQLite's default) | A move that stops halfway leaves some documents at old paths until [`backfillPaths`](/path/api/backfill-paths/) runs |

Works with and without transactions on MongoDB, Postgres, and SQLite.
