```ts
import { backfillPaths } from '@payloadpack/path'

const { left, unchanged, updated } = await backfillPaths({ payload })
```

| Argument      | Purpose                                                                                 | Default                    |
| ------------- | --------------------------------------------------------------------------------------- | -------------------------- |
| `payload`     | Your Payload instance                                                                   | Required                   |
| `collections` | Subset of configured collections to backfill                                            | All configured collections |
| `req`         | Request whose transaction the run should join (such as a [migration's](#how-to-run-it)) | None                       |

## What it returns

```ts
{
  updated: 12,
  unchanged: 3480,
  left: [
    {
      collection: 'pages',
      id: '…',
      refusal: 'Give this document a slug, or a title to make one from.'
    }
  ]
}
```

- **`updated`:** Documents that got a new path or new ancestors (in the document or its latest version).
- **`unchanged`:** Documents that already had the right path and ancestors.
- **`left`:** Documents left untouched, each with its refusal message (or naming the other document at its path). Fix each one before re-running.

<details>
<summary>What ends up in left</summary>

- Never invents slugs. A document without a slug is left with the [refusal](/path/refusals/#slug-and-parent) a save would get, along with every document below it.
- If two documents ended up [at the same path](/path/paths/#one-document-per-path), both are left — each naming the other. Change one document's slug or parent and re-run.
- Passing a collection not given to `pathPlugin()` throws:

  > @payloadpack/path was asked for collections that pathPlugin() wasn't given: notices.

</details>

## When to run it

| Situation                                                                         | Why                                                                                                                |
| --------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| Once, after adding the plugin to a site with existing documents                   | Existing documents have no stored path yet, so `findByPath` won't find them                                        |
| After adding an existing collection to `pathPlugin`                               | Same — pass `collections: ['posts']` to backfill only that collection                                              |
| After bypassing Payload hooks (e.g. an import writing directly with `payload.db`) | Hooks didn't run to set paths. Imports using `payload.create` don't need a backfill                                |
| After adding or removing `localized: true` on a collection with documents         | Once your migration has copied slugs (see [Languages](/path/languages/#switching-a-collection-that-has-documents)) |
| After a rare event listed in [Limits](/path/limits/)                              | A move that stopped halfway without transactions, or a stale path after concurrent moves                           |

- Not part of builds or deploys — normal saves keep paths updated after the initial run.
- In a collection with Payload's hierarchy that already has documents with parents, run it once before deleting anything ([Moves and deletes](/path/moves-and-deletes/#deletes)).
- Safe to run anytime: a second run writes nothing.

## How to run it

<Steps>

1. **Create a script** (`backfillPaths` is a function, not a CLI command).

   ```ts title="scripts/backfill-paths.ts"
   import config from '@payload-config'
   import { backfillPaths } from '@payloadpack/path'
   import { getPayload } from 'payload'

   const payload = await getPayload({ config })
   const { left, unchanged, updated } = await backfillPaths({ payload })

   console.log({ left, unchanged, updated })
   process.exit(0)
   ```

2. **Run it.** Your site can stay live — edits saved before the run reaches a document are kept.

   ```sh
   bunx payload run scripts/backfill-paths.ts
   ```

3. **Fix any `left` items** as described in their refusal messages, then run it again.

</Steps>

### Inside a migration

Pass the migration's `req` so the backfill joins the migration's transaction (and rolls back with it if anything fails):

```ts title="migrations/backfill-paths.ts"
import type { MigrateUpArgs } from '@payloadcms/db-postgres'
import { backfillPaths } from '@payloadpack/path'

export async function up({ payload, req }: MigrateUpArgs): Promise<void> {
  await backfillPaths({ payload, req })
}
```

:::caution
Always pass `req` inside a migration. Without it, a migration that altered a table holds a lock on that table — causing `backfillPaths` to hang on Postgres and fail on SQLite.
:::

## What a run does

| Does                                                                     | Doesn't                                                                                                                       |
| ------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------- |
| Compute every document's path and ancestors, parents first               | Create a new version or run collection hooks                                                                                  |
| Write only what differs, in the document and its latest version          | Call [`onPathsChanged`](/path/api/on-paths-changed/#what-else-to-purge) — purge your cache after a run that updated documents |
| Write each document on its own, so an interrupted run can resume cleanly | Apply a pending draft move on a published document (it stays pending)                                                         |
