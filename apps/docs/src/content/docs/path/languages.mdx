With Payload localization enabled and `localized: true`, each locale has its own slug and path. Without `localized: true`, the collection keeps [one path in every locale](#one-path-in-every-locale).

## A slug per locale

| Team's slug (`en`) | Team's slug (`sv`) | Path in `en`    | Path in `sv`     |
| ------------------ | ------------------ | --------------- | ---------------- |
| `team`             | _(none)_           | `/about/team`   | `/om-oss/team`   |
| `people`           | _(none)_           | `/about/people` | `/om-oss/people` |
| `people`           | `laget`            | `/about/people` | `/om-oss/laget`  |

- **Path rule**: Each locale's path combines that locale's slug with its parent's path in that locale. A `basePath` is the same in every locale.
- **Slug fallback order**: If a locale has no slug, it uses `fallbackLocale` → `defaultLocale` (when fallback is enabled) → any locale that has a slug.
- **Checked per locale**: Taken paths, reserved slugs, and `rootSlug` are checked per locale — `/contact` can be one page in `en` and another page in `sv`.
- **Without drafts**: A locale gets its path when saved in that locale, and the slug it fell back to becomes its own. A locale the document was never saved in has no path.

## Publishing per locale

| Change                                   | What happens                                                                                |
| ---------------------------------------- | ------------------------------------------------------------------------------------------- |
| Draft slug edit on a published locale    | Stays pending until that locale is published                                                |
| Draft slug edit on an unpublished locale | Moves immediately in that locale                                                            |
| Publishing one locale                    | Never moves another locale that has its own slug                                            |
| Draft parent change                      | Stays pending while published in **any** locale (the parent is the same across all locales) |

```ts title="app/[locale]/[[...segments]]/page.tsx"
import { findByPath } from '@payloadpack/path'
import { notFound } from 'next/navigation'
import { getPayload } from 'payload'

import config from '@payload-config'

type Props = { params: Promise<{ locale: string; segments?: string[] }> }

export default async function Page({ params }: Props) {
  const { locale, segments = [] } = await params
  const payload = await getPayload({ config })
  const path = `/${segments.join('/')}`
  const found = await findByPath({ locale, path, payload })
  if (!found) notFound()
  // Render found.document (from found.collection)
}
```

- The locale is never stored in `path`, so your site chooses how to carry it: URL prefix, domain, or cookie.
- Omit `locale` if your site doesn't use localization.
- For language switchers or `hreflang` alternate links, call [`findPaths`](/path/api/find-paths/) or pass [`paths: true`](/path/api/find-by-path/#paths-in-each-locale) to `findByPath`.

## One path in every locale

Without `localized: true`, a collection keeps one path across all locales (like `topics` below):

```ts title="payload.config.ts"
pathPlugin({
  collections: [
    { slug: 'pages', localized: true },
    { slug: 'topics', basePath: '/topics' }
  ]
})
```

- **One slug and one path**: Saving a new slug in any locale renames the document in all locales.
- **Taken in every locale**: A page at `/topics/crops` in any locale blocks a topic at `/topics/crops`, and vice versa.
- **Adding localization later**: Existing slugs and paths stay as stored — nothing to migrate.
- **Drafts & publishing**: Publishing is still per locale if the collection has another localized field (such as a localized title); otherwise one publish publishes every locale at once. A draft's new slug stays a pending move while published in any locale, and publishing in any locale moves the branch in all locales.

## Switching a collection that has documents

:::caution
Adding or removing `localized: true` on a collection with existing documents requires a migration you write yourself. The plugin doesn't copy slugs and won't detect uncopied ones.
:::

<Steps>

1. Copy existing slugs to their new field structure in both the documents and their versions. When removing `localized: true`, choose which locale's slug to keep.

2. Run [`backfillPaths`](/path/api/backfill-paths/) once.

</Steps>
