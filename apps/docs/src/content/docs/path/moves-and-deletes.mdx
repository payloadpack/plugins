## Moves

- Changing a slug or parent updates the entire branch, including latest versions. Because a branch stays in one collection, a move only writes to that collection.
- Every new path in the branch is checked before writing. If any is taken or reserved, the move is [refused](/path/refusals/#taken-paths). There is no branch size limit ([Speed](/path/speed/) shows timings for a 1,000-page branch).
- Saving a draft on a published document moves nothing until it is published. See [Drafts](/path/drafts/).

## Deletes

<PathDiagram>
  <PathTree
    label="Before"
    documents={[
      {
        title: 'Company',
        path: '/company',
        documents: [
          {
            title: 'Team',
            path: '/company/team',
            state: 'removed',
            note: 'deleting',
            documents: [{ title: 'People', path: '/company/team/people' }]
          }
        ]
      }
    ]}
  />
  <PathChange>Team deleted</PathChange>
  <PathTree
    label="After"
    documents={[
      {
        title: 'Company',
        path: '/company',
        documents: [{ title: 'People', path: '/company/people', mark: '/people', note: 'lifted' }]
      }
    ]}
  />
</PathDiagram>

- Deleting a document lifts the documents right below it up one level — to its parent, or to the top level of the collection.
- If a lifted document would land on a taken path, a reserved slug, or `/`, the delete is [refused](/path/refusals/) and nothing moves.
- **With Payload's `trash`**: Sending a document to the trash frees its path without lifting documents below it. Another document can take that path — if it does, restoring the trashed document is refused. Documents below lift only when it is permanently deleted.
- In a collection with `parent: false`, documents have no parents, so deletes lift nothing.

:::caution[With Payload's hierarchy]
If a collection with Payload's hierarchy already had documents with parents before you added the plugin, run [`backfillPaths`](/path/api/backfill-paths/) once before deleting anything. Until then, a delete also deletes the documents right below (Payload's default behavior). If you also set `parent: false` on a hierarchy collection, Payload's default behavior always applies.
:::

## A move that stops halfway

| Database setup                  | If a move or delete fails halfway                                                              |
| ------------------------------- | ---------------------------------------------------------------------------------------------- |
| With transactions               | Everything rolls back — nothing changes                                                        |
| Without them (SQLite's default) | Some documents keep their old paths until you run [`backfillPaths`](/path/api/backfill-paths/) |

See [Limits](/path/limits/) for what else concurrent saves or databases without transactions can leave behind.
