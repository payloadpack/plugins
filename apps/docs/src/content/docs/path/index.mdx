`@payloadpack/path` adds `slug` and an indexed `path` field to the collections you choose. Every path is **unique across all configured collections** — drafts included — and stays updated when editors rename, move, publish, or delete.

```ts title="payload.config.ts"
import { pathPlugin } from '@payloadpack/path'

export default buildConfig({
  plugins: [pathPlugin({ collections: ['pages', 'posts'] })]
})
```

```ts
import { findByPath } from '@payloadpack/path'

const found = await findByPath({ path: '/about/team', payload })
// {
//   collection: 'pages',
//   document: { id: '…', title: 'Team', path: '/about/team', … }
// }
```

Each document can sit below a parent from its own collection — using the plugin's `parent` field or Payload's hierarchy — or have no parent at all (like blog posts). Configure this [per collection](/path/configuration/#collections).

## What you get

- **Unique across collections:** Every path belongs to one document across all configured collections, drafts included. If an editor picks a taken path, the refusal names the document already there.
- **Stored and indexed:** Built from the parent's path, a slash, and the slug — after an optional base path like `/blog`. Saved on the document and indexed.
- **Branches move together:** Rename or move a page or post and every document below it moves too, drafts included.
- **One query per lookup:** `findByPath` runs one indexed query per collection, and zero queries for a reserved path.
- **Home page and reserved slugs:** The top-level page with the slug `home` is served at `/`. `/admin` and `/api` stay reserved for your site.
- **A path per language:** Keep one path across all locales, or give each locale its own path. The locale is never part of the stored path.

## Requirements

| Package or database | Version or setup          |
| ------------------- | ------------------------- |
| `payload`           | 4.0.0-beta.11 or later    |
| MongoDB             | `@payloadcms/db-mongodb`  |
| Postgres            | `@payloadcms/db-postgres` |
| SQLite              | `@payloadcms/db-sqlite`   |

Works with and without database transactions. See [Installation](/path/installation/#transactions).
