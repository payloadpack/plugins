import { Card, CardGrid } from '@astrojs/starlight/components'

```ts title="payload.config.ts"
import { pathPlugin } from '@payloadpack/path'

export default buildConfig({
  plugins: [pathPlugin({ collections: ['pages', 'posts'] })]
})
```

```ts
import { findByPath } from '@payloadpack/path'

const found = await findByPath({ path: '/about/team', payload })
// { collection: 'pages', document: { id: '…', title: 'Team', path: '/about/team', … } }
```

- `@payloadpack/path` adds a slug and a stored path to the documents of the collections you name. It keeps every path correct when editors rename, move, publish and delete.
- A document sits below a parent from its own collection. The plugin's own parent field or Payload's hierarchy stores the parent. A collection such as posts can also have no parents. You choose [per collection](/path/configuration/#collections).

## What you get

<CardGrid>
  <Card title="A stored path">
    The parent's path, a slash and the slug, after an optional base path such as `/blog`. Saved on the document and indexed.
  </Card>
  <Card title="One document per path">
    Across all your collections, drafts included. If an editor picks a taken path, the plugin names the document at it.
  </Card>
  <Card title="Branches that move along">
    Rename or move a page or a post, and every document below it moves too, drafts included.
  </Card>
  <Card title="A home page and reserved slugs">
    The top-level page with the slug `home` is at `/`. `/admin` and `/api` stay free for your site.
  </Card>
  <Card title="A path per language">
    A collection has one path for all locales, or one path per locale if you choose. The path never contains the locale.
  </Card>
  <Card title="One query per lookup">
    `findByPath` queries each collection once, on its index. For a reserved path it doesn't query at all.
  </Card>
</CardGrid>

## Why the path is stored

You can find a page from slugs and parents, with one query per segment. Every link your site shows then needs the same steps in reverse. With a stored path, a lookup is one query at any depth, and a link's path is on the document it points to.

[Speed](/path/speed/) measures both on a MongoDB server on another machine, against the other ways we built and tried, and shows [where the others win](/path/speed/#where-the-others-win).

## Requirements

| Package or database | Version or setup          |
| ------------------- | ------------------------- |
| `payload`           | 4.0.0-beta.10 or later    |
| MongoDB             | `@payloadcms/db-mongodb`  |
| Postgres            | `@payloadcms/db-postgres` |
| SQLite              | `@payloadcms/db-sqlite`   |

The plugin works with database transactions and without them. See [Installation](/path/installation/#transactions).
