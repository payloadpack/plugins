
| Key                | What it sets                                                                                                                                              | Default                                                 |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------- |
| `collections`      | The [collections](#collections) whose documents get a path. Give each by its slug or as `{ slug, basePath, parent, localized, slugField, parentField }`   |                                                         |
| `rootSlug`         | The slug that makes a top-level document the [home page](#home-page)                                                                                      | `home`                                                  |
| `reservedSegments` | [Segments your site serves itself](#reserved-slugs), as a list or each with a reason                                                                      | Payload's admin and API routes                          |
| `slugify`          | Makes [a slug](/path/paths/#the-slug) from a title or a typed slug, also for the slug field's button. Same shape as Payload's own `slugify`, may be async | Removes accents from Latin letters, keeps other scripts |
| `onPathsChanged`   | A function that gets [the paths that changed](/path/api/on-paths-changed/)                                                                                | none                                                    |

## Collections

```ts title="payload.config.ts"
pathPlugin({
  collections: [
    { slug: 'pages', localized: true },
    { slug: 'posts', basePath: '/blog', parent: false },
    { slug: 'topics', basePath: '/topics' }
  ]
})
```

| Key           | What it sets                                                                                                               | Default                                         |
| ------------- | -------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------- |
| `slug`        | The collection                                                                                                             |                                                 |
| `basePath`    | What the paths of its top-level documents start with, such as `/blog`                                                      | None, so they start at the root                 |
| `parent`      | `false` when its documents have [no parent](#the-parent)                                                                   | Its documents have a parent                     |
| `localized`   | `true` when its documents have [a path per locale](#a-path-per-locale)                                                     | One slug and one path, the same in every locale |
| `slugField`   | [Field options](#field-options) for the slug field: `access`, `admin`, `hooks`, `label` and `validate`                     | The plugin's own                                |
| `parentField` | [Field options](#field-options) for the plugin's own parent field: `access`, `admin`, `filterOptions`, `hooks` and `label` | The plugin's own                                |

- With `basePath: '/blog'`, a top-level post is at `/blog/my-post`. A base path is not a document, so a page can be at `/blog` next to the posts.
- A parent is always a document of the same collection, so a post can't sit below a page. Each path still belongs to one document across all your collections.

### The parent

<Tabs>
<TabItem label="The plugin's own parent">

```ts title="payload.config.ts"
pathPlugin({ collections: ['pages'] })
```

- The default, for a collection given by its slug or as an object without `parent`.
- The collection gets a `parent` field in the sidebar, where an editor picks a document of the same collection.

</TabItem>
<TabItem label="No parent">

```ts title="payload.config.ts"
pathPlugin({ collections: [{ slug: 'posts', basePath: '/blog', parent: false }] })
```

- For a collection whose documents never sit below each other. Each document's path is the base path, a slash and its slug, such as `/blog/hello-world`.
- The collection gets no `parent` field. A rename moves only that one document, and a delete lifts nothing.
- `parent` accepts only `false`.

</TabItem>
<TabItem label="Payload's hierarchy">

```ts title="payload.config.ts"
export default buildConfig({
  collections: [{ slug: 'topics', hierarchy: true, fields: [{ name: 'title', type: 'text' }] }],
  plugins: [pathPlugin({ collections: [{ slug: 'topics', basePath: '/topics' }] })]
})
```

- For a collection whose own config has Payload's `hierarchy`, or its `folders` or `tags` preset. The plugin adds no `parent` field. It reads the field that `hierarchy.parentFieldName` names, by default `_h_topics` here.
- Editors get Payload's tree in the admin. They move a document with the button in its header.
- Everything else works as with the plugin's own parent. A [delete](/path/moves-and-deletes/#deletes) lifts the documents right below one level. Payload alone would delete them. Read [Payload's hierarchy](#payloads-hierarchy) before you start.

</TabItem>
</Tabs>

### Payload's hierarchy

:::caution

- Set `hierarchy` to `true`, or to an object with `parentFieldName`. In Payload 4.0.0-beta.10, an object without `parentFieldName` breaks every delete in the collection, with or without the plugin.
- If the collection already has documents with parents, run [`backfillPaths`](/path/api/backfill-paths/) once after you add the plugin, before you delete anything in it. Until then, a delete also deletes the documents right below, as Payload does without the plugin.

:::

<details>
<summary>Good to know</summary>

- Payload's hierarchy has no parent field in the form. So a refused parent, such as a document below itself, shows on the slug field.
- With `parent: false` as well, the collection keeps Payload's tree in the admin, but its paths have no parent in them. The plugin lifts nothing there, so a delete deletes the documents right below, as Payload does.

</details>

### A path per locale

  <PathTree label="pages in sv" documents={[{ title: 'About', path: '/om-oss', mark: '/om-oss' }]} />
</PathDiagram>

- With `localized: true`, a collection's documents have a slug and a path per locale. Without it, they have one slug and one path for all locales, even when your Payload config has localization.
- `localized` accepts only `true`. It works with `basePath`, `parent: false` and Payload's hierarchy. In a site without localization it changes nothing.
- [Languages](/path/languages/) explains how each locale gets its path, and what to do in a collection that already has documents.

### Field options

```ts title="payload.config.ts"
pathPlugin({
  collections: [
    {
      slug: 'pages',
      slugField: { access: { update: ({ req }) => req.locale === 'en' } }
    }
  ]
})
```

Here only the default locale can change a slug. In other locales the admin shows the slug as read-only, without its lock and refresh buttons. If a save sends a different slug, the slug and the path stay the same, and the rest of the page is saved.

| Option                        | How the plugin uses it                                                                                                                                                |
| ----------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `access`, `label`, `validate` | As you set them                                                                                                                                                       |
| `admin`                       | Merged over the plugin's own, `components` too, so the slug field keeps its lock and sidebar place unless you change them                                             |
| `hooks`                       | Run after the plugin's own, so a `beforeValidate` hook gets the slug already cleaned                                                                                  |
| `filterOptions`               | Combined with the plugin's own, so the parent picker still leaves out the document itself and the home page. Accepts the same values as Payload's own `filterOptions` |

`parentField` is only for a collection with the plugin's own parent, not for one with `parent: false` or Payload's hierarchy.

## Home page

```ts title="payload.config.ts"
pathPlugin({ collections: ['pages', 'posts'], rootSlug: 'start' })
```

- The top-level document with this slug is the home page, and its path is `/`. Without `rootSlug`, the slug is `home`.
- Only a top-level document in a collection without a base path can be the home page. A page with the slug `start` below another page is at `/about/start`. With posts at `/blog`, a post with the slug `start` is at `/blog/start`.
- No document can sit below the home page. A document below it would get a path starting with `/start/`, but the home page is at `/`, not `/start`.

<details>
<summary>Good to know</summary>

In a collection with a path per locale, this is checked per locale. A page is the home page in each locale where its slug is the root slug.

</details>

## Reserved slugs

```ts title="payload.config.ts"
pathPlugin({
  collections: ['pages', 'posts'],
  reservedSegments: {
    root: { admin: 'the CMS', api: "the CMS's API" },
    anyDepth: { '-': 'starts the page and filters of a listing' }
  }
})
```

- A segment in `root` is refused as the first segment of a path, base paths included. Below a parent it is allowed, so `/docs/api` is fine.
- A segment in `anyDepth` is refused anywhere in a path, such as the `-` in `/journal/-/page/2`.
- Without `root`, the plugin reserves the first segment of Payload's `routes.admin` and `routes.api`. If you set `root`, your list replaces those, so include them, as above.

<details>
<summary>Good to know</summary>

- Each also accepts a list, such as `root: ['admin', 'api', 'shop']`. The [refusal](/path/refusals/#reserved-slugs) then gives no reason.
- A move or a delete that would put a document at a reserved slug is refused too.
- `findByPath` returns `null` for a path with a reserved slug, without querying the database.

</details>

## Slugify

```ts title="payload.config.ts"
import { defaultSlugify, pathPlugin } from '@payloadpack/path'

pathPlugin({
  collections: ['pages', 'posts'],
  // toLatin is yours.
  slugify: (args) => defaultSlugify({ ...args, valueToSlugify: toLatin(args.valueToSlugify) })
})
```

The plugin uses `defaultSlugify` when you don't set your own `slugify`. Your own rule can run before or after it.

## The fields it adds

| Field       | What it stores                                                                                                                                               | Which collections get it                                           |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------ |
| `parent`    | The parent, a relationship to the document's own collection. Its picker leaves out the document itself and the home page                                     | Those with the plugin's own parent                                 |
| `slug`      | The document's own segment of the path, shown as Payload's own slug field, with its lock                                                                     | All                                                                |
| `path`      | The stored path, read-only and indexed                                                                                                                       | All                                                                |
| `ancestors` | The ids of the documents above, top-down, as an indexed relationship to the document's own collection. The API returns and filters by it, the admin hides it | Those whose documents have a parent, the plugin's own or Payload's |

- The plugin adds these after each collection's own fields.
- In a collection with `localized: true`, `slug` and `path` are localized fields.

## When the config is wrong

The plugin checks its options when Payload builds the config, and stops with one of these messages:

| Message                                                                                                                 | What to change                                                            |
| ----------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| @payloadpack/path was given collections the config doesn't have: posts.                                                 | Fix the slug, or put the plugin after the plugin that adds the collection |
| @payloadpack/path was given pages more than once, so list each collection once.                                         | Keep one entry for the collection, with its base path if it has one       |
| @payloadpack/path adds slug to pages, so remove its own.                                                                | Remove or rename the collection's own field                               |
| @payloadpack/path adds no parent field to posts, so leave out its parentField.                                          | Remove `parentField`. Only the plugin's own parent field uses it          |
| @payloadpack/path was given the base path blog for posts, which doesn't start with a slash, so start it with one.       | Write it as `/blog`                                                       |
| @payloadpack/path was given the base path /blog/ for posts, which ends with a slash, so remove that slash.              | Write it as `/blog`                                                       |
| @payloadpack/path was given the base path /blog//news for posts, which has an empty segment, so remove the extra slash. | Write it as `/blog/news`                                                  |
| @payloadpack/path was given the base path / for posts, which is the root already, so leave basePath out.                | Remove `basePath`, or give it a segment such as `/blog`                   |
