```ts title="payload.config.ts"
pathPlugin({
  collections: [
    'pages',
    { slug: 'posts', basePath: '/blog', parent: false }
  ],
  rootSlug: 'home',
  reservedSegments: {
    root: { admin: 'the CMS', api: "the CMS's API" },

  },
  // makeSlug is yours
  slugify: ({ valueToSlugify }) => makeSlug(valueToSlugify),
  onPathsChanged: ({ changedPaths, payload, req }) => {
    // Purge your cache or create redirects here
  }
})
```

| Option             | Purpose                                                                                                                               | Default                                                 |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------- |
| `collections`      | [Collections](#collections) that get a path. Pass a slug string or `{ slug, basePath, parent, localized, slugField, parentField }`    | Required                                                |
| `rootSlug`         | Top-level slug used for the [home page](#home-page) (`/`)                                                                             | `'home'`                                                |
| `reservedSegments` | [Slugs your site reserves](#reserved-slugs), as a string list or `{ segment: reason }`                                                | Payload's admin and API routes                          |
| `slugify`          | Builds [a slug](/path/paths/#the-slug) from a title or input (also for the refresh button). Same signature as Payload's; may be async | Removes accents from Latin letters, keeps other scripts |
| `onPathsChanged`   | Callback that receives [changed published paths](/path/api/on-paths-changed/)                                                         | None                                                    |

## Collections

```ts title="payload.config.ts"
pathPlugin({
  collections: [
    { slug: 'pages', localized: true },
    { slug: 'posts', basePath: '/blog', parent: false },
    { slug: 'topics', basePath: '/topics' }
  ]
})
```

| Key           | Purpose                                                                                                         | Default                                  |
| ------------- | --------------------------------------------------------------------------------------------------------------- | ---------------------------------------- |
| `slug`        | Collection slug                                                                                                 | Required                                 |
| `basePath`    | Base path for top-level documents, such as `/blog`                                                              | None (starts at `/`)                     |
| `parent`      | Set `false` if documents have [no parent](#the-parent)                                                          | Documents have a parent                  |
| `localized`   | Set `true` for [a path per locale](#a-path-per-locale)                                                          | One slug and one path across all locales |
| `slugField`   | [Field options](#field-options) for `slug`: `access`, `admin`, `hooks`, `label`, `validate`                     | Plugin defaults                          |
| `parentField` | [Field options](#field-options) for the plugin's `parent`: `access`, `admin`, `filterOptions`, `hooks`, `label` | Plugin defaults                          |

- With `basePath: '/blog'`, a top-level post lives at `/blog/my-post`. Because a base path is not a document, a page can still live at `/blog`.
- Parents always come from the same collection (a post can't sit below a page). Paths are still unique across **all** collections.

### The parent

<Tabs>
<TabItem label="Plugin's parent field">

```ts title="payload.config.ts"
pathPlugin({ collections: ['pages'] })
```

- Default when you pass a collection slug or an object without `parent`.
- Adds a `parent` relationship field in the sidebar that picks from the same collection.

</TabItem>
<TabItem label="No parent">

```ts title="payload.config.ts"
pathPlugin({ collections: [{ slug: 'posts', basePath: '/blog', parent: false }] })
```

- For flat collections whose documents never sit below each other. Each path is `basePath + / + slug` (e.g. `/blog/hello-world`).
- Adds no `parent` field. Renames move only that document, and deletes lift nothing.
- `parent` only accepts `false`.

</TabItem>
<TabItem label="Payload's hierarchy">

```ts title="payload.config.ts"
export default buildConfig({
  collections: [{ slug: 'topics', hierarchy: true, fields: [{ name: 'title', type: 'text' }] }],
  plugins: [pathPlugin({ collections: [{ slug: 'topics', basePath: '/topics' }] })]
})
```

- Automatic when the collection uses Payload's `hierarchy`, `folders`, or `tags` preset. The plugin adds no `parent` field and reads `hierarchy.parentFieldName` (e.g. `_h_topics`).
- Editors keep Payload's admin tree and move documents with the header button.
- [Deletes](/path/moves-and-deletes/#deletes) lift documents right below one level instead of deleting them like Payload alone does. Read [Payload's hierarchy](#payloads-hierarchy) below before starting.

</TabItem>
</Tabs>

### Payload's hierarchy

:::caution

- Set `hierarchy` to `true` or to an object that includes `parentFieldName`. In Payload `4.0.0-beta.11`, an object without `parentFieldName` breaks every delete in that collection, with or without the plugin.
- If the collection already has documents with parents, run [`backfillPaths`](/path/api/backfill-paths/) once after adding the plugin and before deleting anything. Until then, deletes also delete the documents below, as Payload does without the plugin.

:::

<details>
<summary>More details</summary>

- Payload's hierarchy has no `parent` field in the edit form, so parent refusals (like placing a document below itself) appear on the `slug` field.
- If you also set `parent: false` on a collection with Payload's hierarchy, the collection keeps Payload's admin tree, but paths don't include parents and deletes don't lift — Payload deletes the documents below as usual.

</details>

### A path per locale

<PathDiagram layout="columns">
  <PathTree label="pages (en)" documents={[{ title: 'About', path: '/about', mark: '/about' }]} />
  <PathTree label="pages (sv)" documents={[{ title: 'About', path: '/om-oss', mark: '/om-oss' }]} />
</PathDiagram>

- Set `localized: true` to give each locale its own slug and path. Without it, documents keep one slug and one path across all locales — even when Payload localization is enabled.
- `localized` only accepts `true`. It works with `basePath`, `parent: false`, and Payload's hierarchy, and does nothing if your Payload config has no localization.
- See [Languages](/path/languages/) for fallback rules and switching a collection that already has documents.

### Field options

```ts title="payload.config.ts"
pathPlugin({
  collections: [
    {
      slug: 'pages',
      slugField: { access: { update: ({ req }) => req.locale === 'en' } }
    }
  ]
})
```

In this example, only `en` can update the slug. Other locales see `slug` as read-only (no lock or refresh buttons). If a save sends a different slug, the slug and path stay unchanged while the rest of the document saves normally.

| Option                        | How it combines with the plugin's defaults                                                                                                     |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| `access`, `label`, `validate` | Applied as given                                                                                                                               |
| `admin`                       | Merged over the plugin's `admin` (including `components`), so `slug` keeps its lock and sidebar position unless you change them                |
| `hooks`                       | Runs after the plugin's hooks, so `beforeValidate` receives the cleaned slug                                                                   |
| `filterOptions`               | Combined with the plugin's filter, so the parent picker still hides the document itself and the home page. Accepts all Payload `filterOptions` |

`parentField` only applies to collections using the plugin's own `parent` field (not `parent: false` or Payload's hierarchy).

## Home page

```ts title="payload.config.ts"
pathPlugin({ collections: ['pages', 'posts'], rootSlug: 'start' })
```

    documents={[{ title: 'Start', path: '/blog/start', basePath: '/blog', mark: '/start', note: 'has basePath' }]}
  />

- The top-level document with slug `rootSlug` (default `'home'`) gets `/`.
- Only top-level documents in collections without a `basePath` can be the home page.
- No document can sit below the home page (its path would start with `/start/`, even though the home page is at `/`).
- With `localized: true`, this is checked per locale — a page is the home page in each locale where its slug matches `rootSlug`.

## Reserved slugs

```ts title="payload.config.ts"
pathPlugin({
  collections: ['pages', 'posts'],
  reservedSegments: {
    root: { admin: 'the CMS', api: "the CMS's API" },
    anyDepth: { '-': 'starts the page and filters of a listing' }
  }
})
```

<PathAnatomy
  rows={[
    {
      parts: [{ text: '/admin', label: 'first segment', kind: 'refused' }],
      badge: 'Refused (root)',
      status: 'refused'
    },
    {
      parts: [
        { text: '/docs', label: 'parent' },
        { text: '/api', label: 'below parent', kind: 'brand' }
      ],
      badge: 'Allowed',
      status: 'ok'
    },
    {
      parts: [
        { text: '/journal', label: 'parent' },
        { text: '/-', label: 'any depth', kind: 'refused' },
        { text: '/page/2', kind: 'muted' }
      ],
      badge: 'Refused (anyDepth)',
      status: 'refused'
    }
  ]}
/>

- `root` refuses a segment only as the first segment of a path (including a `basePath`). Below a parent, it's allowed (`/docs/api` works).
- `anyDepth` refuses a segment anywhere in a path (like `-` in `/journal/-/page/2`).
- If you omit `root`, the plugin reserves the first segments of Payload's `routes.admin` and `routes.api`. Setting `root` replaces those defaults, so include them as shown above.

<details>
<summary>More details</summary>

- Both `root` and `anyDepth` also accept a plain string array, such as `root: ['admin', 'api', 'shop']`. The [refusal](/path/refusals/#reserved-slugs) then omits a custom reason.
- Moves and deletes that would land a document on a reserved slug are refused too.
- `findByPath` returns `null` for a reserved path without querying the database.

</details>

## Slugify

```ts title="payload.config.ts"
import { defaultSlugify, pathPlugin } from '@payloadpack/path'

pathPlugin({
  collections: ['pages', 'posts'],
  // toLatin is yours
  slugify: (args) => {
    const valueToSlugify = toLatin(args.valueToSlugify)
    return defaultSlugify({ ...args, valueToSlugify })
  }
})
```

The plugin uses `defaultSlugify` when `slugify` isn't set. Wrap it to run your own logic before or after.

## The fields it adds

<SidebarPreview />

| Field       | What it stores                                                                                                                                    | Added to                                                    |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| `parent`    | Relationship to the same collection; picker hides the document itself and the home page                                                           | Collections using the plugin's own parent                   |
| `slug`      | The document's path segment, rendered with Payload's lockable slug UI                                                                             | All configured collections                                  |
| `path`      | Stored path, read-only and indexed                                                                                                                | All configured collections                                  |
| `ancestors` | Top-down IDs of documents above, as an indexed relationship to the same collection. Available in the API (returned & filterable), hidden in admin | Collections with a parent (plugin's or Payload's hierarchy) |

- Added after each collection's own fields.
- With `localized: true`, `slug` and `path` are localized fields.

## When the config is wrong

Invalid options stop Payload while building the config with one of these messages:

| Message                                                                                                                 | Fix                                                                       |
| ----------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| @payloadpack/path was given collections the config doesn't have: posts.                                                 | Fix the collection slug, or place `pathPlugin` after the plugin adding it |
| @payloadpack/path was given pages more than once, so list each collection once.                                         | List each collection once (with its options object if needed)             |
| @payloadpack/path adds slug to pages, so remove its own.                                                                | Remove or rename the collection's own field                               |
| @payloadpack/path adds no parent field to posts, so leave out its parentField.                                          | Remove `parentField` — only the plugin's own `parent` field uses it       |
| @payloadpack/path was given the base path blog for posts, which doesn't start with a slash, so start it with one.       | Change to `/blog`                                                         |
| @payloadpack/path was given the base path /blog/ for posts, which ends with a slash, so remove that slash.              | Change to `/blog`                                                         |
| @payloadpack/path was given the base path /blog//news for posts, which has an empty segment, so remove the extra slash. | Change to `/blog/news`                                                    |
| @payloadpack/path was given the base path / for posts, which is the root already, so leave basePath out.                | Remove `basePath`, or set a segment like `/blog`                          |
