---
title: How move suggestions work
description: What moves and deletes suggest, how editor notices work on moved pages, and how collisions, move-backs, and swaps behave.
---

When your site reports changed paths to [`suggestRedirects`](/redirects/api/suggest-redirects/) — from its own hook or from [`onPathsChanged`](/path/api/on-paths-changed/) in `@payloadpack/path` — every published path that changes gets a suggestion. A suggestion is saved with status **Suggested** and answers nobody until an editor says yes. Without calling `suggestRedirects`, moves suggest nothing; see [Suggest redirects when pages move](/redirects/suggest-on-move/).

## What a move suggests

| Editor action                                         | Redirect suggested                                                        |
| ----------------------------------------------------- | ------------------------------------------------------------------------- |
| Rename `/about-us` to `/company`, with pages below it | One, from `/about-us` (**Path and subpaths**) to the page                 |
| Move `/team` below `/company`                         | One, from `/team` (**Path and subpaths**) to the page                     |
| Change a post's slug at `/blog/spring-menu`           | One, from `/blog/spring-menu` (**Path and subpaths**) to the post         |
| Give the home page at `/` another slug                | One, from `/` (**Exact path**) to the page, since every path is below `/` |
| Delete `/workshops`, lifting `/workshops/pottery`     | One for each lifted page, such as `/workshops/pottery` to the page        |

- **Permanent document targets:** Every suggestion is permanent (308) and points to the document. Once an editor says yes, it follows the document through every later move without creating chains.
- **One suggestion per moved branch:** A branch of any size gets one suggestion from the document at its top, covering every page below. Moving a page with 1,000 pages below writes as much as moving one with 3.
- **Lifted and split pages:** A page lifted by a delete, or moved somewhere other than below its moved parent, gets a suggestion of its own.
- **Unpublished before moving:** A page that is unpublished, moved, and published again gets no suggestion because it gave up its old path when it was unpublished.
- **`Path and subpaths` match:** Suggestions use **Path and subpaths** (except from `/`, which uses **Exact path**). Only suggestions have **Path and subpaths**; editors creating a redirect manually pick **Exact path** or **Regex**.

## Reviewing suggestions on the moved page

Right after a save that moves a document, the admin displays a notice above its fields for each suggestion targeting that document:

> This page moved from /about-us to /company. Should visitors who ask for /about-us be sent here?

The notice names the document by its collection's singular label in lowercase (such as `news item`) when that label is a plain string, and falls back to `page` otherwise. It reads the document as the signed-in editor (drafts included, in the editor's locale) and calls `buildDocumentPath`; when `buildDocumentPath` builds no path for it, the notice leaves out "to /company".

- **Yes, redirect them** sets the redirect's status to **On**, so `/about-us` and its subpaths send visitors to the document.
- **Edit** opens the suggestion in the Redirects collection so the editor can change it before setting status to **On**.
- **No** deletes the suggestion, and `/about-us` answers 404 as before.

**Yes, redirect them** and **No** act through the Redirects collection's REST API as the signed-in editor and only change a redirect whose status is still **Suggested**. Your collection access control decides who can answer, and answering a notice someone else already answered changes nothing. The plugin prepends a `redirectSuggestions` UI field (which stores no data) to every collection listed in `collections`.

## Unanswered suggestions and deletes

Moves through the Local API, bulk edits, or deletes that lift child pages move documents nobody has open. Their suggestions wait in the **Redirects** list with status **Suggested** and appear as notices the next time someone opens the moved document. An editor can answer in either place: pick **On** in the list, or delete the redirect. Until then, the old path answers 404.

When a document is deleted:

- **Permanent delete:** An `afterDelete` hook deletes all **Suggested** redirects targeting the deleted document.
- **Trash and failed deletes:** A document in the trash, or a document whose delete fails, keeps its suggestions until it is permanently deleted.
- **Editor redirects:** Redirects with status **On** or **Off** targeting a deleted document stay in the collection and send nobody.
- **Refused cleanup:** If a site hook refuses to delete a suggestion during a document delete, that suggestion stays without failing the document's delete.

## When a redirect already holds the old path

Because `from` is unique, a move never overwrites a redirect an editor created:

- **Existing `On` or `Off` redirect:** The existing redirect stays as it is and no suggestion is written from that old path. Instead, each document right below that moved with it (and was passed in `changedPaths`) gets a suggestion of its own from its old path and subpaths.
- **Earlier `Suggested` redirect:** An earlier suggestion at that old path gives way to the newer move's suggestion.

## Moving back and swapping paths

When a document moves to or is published at a path:

- Any **Suggested** redirect at that new path is deleted, because a document holds that path now.
- Any redirect at that new path targeting that same document is deleted regardless of status (**On**, **Off**, or **Suggested**), so the document never redirects to itself.
- Editor redirects (**On** or **Off**) at that new path targeting anything else stay untouched.

As a result:

- **Moving back:** A page that moves back to its old path removes its own redirect there and gets a suggestion from the path it just left.
- **Swapping paths in one change:** When two pages swap paths in one change, neither gets a suggestion because both old paths are now held by documents. Pages right below each get their own suggestions.
- **Circles from accepted redirects:** If redirects an editor turned **On** form a circle (such as renaming a parent, creating a new page at its old path, and moving a child below it), [`findRedirect`](/redirects/api/find-redirect/) with `hasDocument` answers `null`, and your site answers 404.

## What a move writes

- **Configured collections only:** Only collections listed in `collections` of [`redirectsPlugin()`](/redirects/configuration/) get suggestions. A document in another collection suggests nothing, though arriving at a path still deletes any suggestion waiting at that path.
- **In the save's transaction:** Suggestions are written through the save's `req` with `overrideAccess: true`, so with transactions a failed save rolls them back, and your hooks on the Redirects collection run. See [Transactions](/redirects/suggest-on-move/#transactions).
- **Cleaned From:** Each suggestion's `from` is stored lowercased and normalized like any path **From**. An old path over 2,048 bytes in UTF-8 gets no suggestion and does not fail the move.
- **Localization:** A move in a locale suggests a redirect from that locale's old path. A collection with one shared path across all locales gets one suggestion even when reported once per locale. See [Use with localization](/redirects/localization/).
