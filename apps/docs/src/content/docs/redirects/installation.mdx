---
title: Installation
description: Install @payloadpack/redirects, configure redirectsPlugin, run a migration on Postgres or SQLite, and answer redirects in your Next.js page route.
---

import { Steps, TabItem, Tabs } from '@astrojs/starlight/components'

**Prerequisites:** Payload 4.0.0-beta.11 or later with MongoDB, Postgres, or SQLite, and a Next.js App Router site. Peer dependencies are `payload`, `@payloadcms/ui`, and `react`, which a Payload app with the admin already has.

<Steps>

1. **Install the package.**

   ```sh
   bun add @payloadpack/redirects
   ```

   Or use `npm install`, `pnpm add`, or `yarn add`.

2. **Add the plugin.** Name the collections a redirect can send visitors to and pass `buildDocumentPath` to build a document's path from the document. Pass `documentSelect` so a lookup reads only the fields `buildDocumentPath` uses.

   <Tabs>

   <TabItem label="Without @payloadpack/path">

   ```ts title="payload.config.ts"
   import { redirectsPlugin } from '@payloadpack/redirects'
   import { buildConfig } from 'payload'

   export default buildConfig({
     plugins: [
       redirectsPlugin({
         collections: ['pages'],
         buildDocumentPath: ({ document }) => `/${document.slug}`,
         documentSelect: { slug: true }
       })
     ]
   })
   ```

   </TabItem>

   <TabItem label="With @payloadpack/path">

   ```ts title="payload.config.ts"
   import { pathPlugin } from '@payloadpack/path'
   import { redirectsPlugin } from '@payloadpack/redirects'
   import { buildConfig } from 'payload'

   export default buildConfig({
     plugins: [
       pathPlugin({ collections: ['pages'] }),
       redirectsPlugin({
         collections: ['pages'],
         buildDocumentPath: ({ document }) => document.path,
         documentSelect: { path: true }
       })
     ]
   })
   ```

   </TabItem>

   </Tabs>

   See [`buildDocumentPath`](/redirects/configuration/#builddocumentpath) for multiple collections or custom path shapes.

3. **Create a migration** on Postgres and SQLite for the Redirects collection the plugin adds. In development with `push: true`, Payload adds the tables automatically.

   ```sh
   bunx payload migrate:create
   ```

4. **Allow visitors to read the collections a redirect can send visitors to.** A lookup reads a document target as a visitor, so a document visitors cannot read sends nobody. Payload 4 lets only users of the admin read a collection unless you set `access.read`.

   ```ts title="collections/pages.ts"
   access: {
     read: ({ req: { payload, user } }) => user?.collection === payload.config.admin.user || { _status: { equals: 'published' } }
   }
   ```

5. **Answer redirects in your page route.** Ask `findRedirect` only when no page holds the path, so normal page views run zero redirect queries.

   <Tabs>

   <TabItem label="Without @payloadpack/path">

   Write a page lookup for your site that reads as a visitor and returns the page or `null`. Adjust the `where` clause to match how your site stores a page's path.

   ```ts title="find-page.ts"
   import type { Payload } from 'payload'

   export async function findPage({ path, payload }: { path: string; payload: Payload }) {
     const { docs } = await payload.find({
       collection: 'pages',
       depth: 0,
       limit: 1,
       overrideAccess: false,
       pagination: false,
       select: {},
       where: { path: { equals: path } }
     })
     return docs[0] ?? null
   }
   ```

   Then use the page route in the **With @payloadpack/path** tab with your own lookup in both places it calls `findByPath`: to find the page at the path, and in `hasDocument`. Render the page your lookup returns, and have it select the fields you render.

   </TabItem>

   <TabItem label="With @payloadpack/path">

   ```tsx title="app/(frontend)/[[...segments]]/page.tsx"
   import config from '@payload-config'
   import { findByPath } from '@payloadpack/path'
   import { findRedirect } from '@payloadpack/redirects'
   import { notFound, permanentRedirect, redirect } from 'next/navigation'
   import { getPayload } from 'payload'

   export default async function SitePage({ params }: { params: Promise<{ segments?: string[] }> }) {
     const { segments = [] } = await params
     const payload = await getPayload({ config })
     // Next gives each segment encoded, so /öppettider comes as %C3%B6ppettider.
     const path = `/${segments.map(decodeURIComponent).join('/')}`

     const found = await findByPath({ path, payload })
     if (found) return <h1>{found.document.title}</h1>

     // With hasDocument, a redirect that lands on a path no document holds is looked up again, so a
     // visitor takes one hop through a chain.
     const { foundRedirect } = await findRedirect({
       hasDocument: async (nextPath) => (await findByPath({ path: nextPath, payload })) !== null,
       path,
       payload
     })
     if (!foundRedirect) notFound()
     if (foundRedirect.permanent) permanentRedirect(foundRedirect.destination)
     redirect(foundRedirect.destination)
   }
   ```

   </TabItem>

   </Tabs>

   The two page lookups ask about different paths: the first asks whether a page holds the path the visitor asked for, and renders it with no redirect lookup at all. `findRedirect` never asks `hasDocument` about that path: it asks only about the path a found redirect sends visitors to, to stop there or follow the next redirect, and not at all when that is the path of the page the redirect targets. `hasDocument` is optional: without it, the first redirect is the answer.

   `permanentRedirect` answers 308 and `redirect` answers 307. See [`findRedirect`](/redirects/api/find-redirect/).

6. **Generate the import map and types.** This registers the move notice component (`@payloadpack/redirects/client#SuggestionNotices`) in the admin and adds the `Redirect` collection to your Payload types.

   ```sh
   bunx payload generate:importmap
   bunx payload generate:types
   ```

</Steps>
